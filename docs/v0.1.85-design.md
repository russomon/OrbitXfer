# v0.1.85 Design Doc — Chat-while-you-transfer

> Status: agreed, implementation underway.
> Approved verbally in conversation on 2026-06-08.
> Supersedes v0.1.84's Shareable Code (pair) flow.

## Goal

Add a real-time chat channel between sender and receiver during (and after) a v0.1.83-style ticket transfer, *without* touching the existing transfer flow. Strip v0.1.84's pair-by-code machinery completely. The PAKE wormhole "Connect by Code" is deferred to a later release.

## Architecture

Two ALPNs on each side's iroh endpoint, lifetimes independent:

```
Sender endpoint                            Receiver endpoint
┌─────────────────────────┐               ┌─────────────────────────┐
│ iroh_blobs::ALPN        │◄── conn1 ────►│ (blob client)           │
│ orbitxfer/chat/1 ALPN   │◄── conn2 ────►│ (chat client)           │
│ orbitxfer/label/0 ALPN  │◄── conn3 ────►│ (label, existing v0.1.71)│
└─────────────────────────┘               └─────────────────────────┘
     ▲ stdin/stdout                            ▲ stdin/stdout
     │                                         │
   Tauri sidecar (send)                     Tauri sidecar (receive)
     │ Tauri commands ◄────────► React        │
     ▼                                         ▼
   Send window: Send panel + Chat panel    Receive window: Receive panel + Chat panel
```

One sidecar per side; chat is just another ALPN on the same iroh router (Approach A). Chat connection opens at the same time as the blob connection; outlives it on Stop Send / Stop Receive / transfer complete.

## Protocol: `orbitxfer/chat/1`

**Frame:** 4-byte big-endian length prefix + JSON body. Max body 4 KiB (bounds memory).

**Messages:**
```typescript
type ChatMessage =
  | { type: "Hello"; proto_version: 1; label?: string }   // first frame each side sends
  | { type: "Text";  body: string; sent_at_unix_ms: number }
  | { type: "Bye" }                                       // graceful close
```

**Handshake:**
1. iroh-TLS connection establishes (no PAKE — implicit auth via the NodeID, which only someone with the ticket can dial).
2. Each side sends `Hello` immediately. `label` defaults to `receiver_label` (the v0.1.71 nickname) on the receiver side, or `"Sender"` on the sender side.
3. Either side may send `Text` at any time. Server-side NFC normalization on inbound text; drop control chars except `\n`; truncate to 4 KiB.
4. Either side sends `Bye` to close; the receiver of `Bye` should not send more.

## CLI changes (`OrbitXfer-iroh-cli/`)

**Delete:** `src/pair.rs`, the `pair-host` / `pair-join` subcommand dispatch in `main.rs`, the pair-related Cargo.toml deps (`pake-cpace`, `argon2`, `chacha20poly1305`, `hkdf`, `sha2`, `eff-wordlist`, `postcard`, `rand_core`, `blake3`). Bump `CLI_VERSION` to `"0.1.85"`.

**Add `src/chat.rs`** (~250 lines):
- `ChatMessage` enum + serde
- `ChatProtocol` (`ProtocolHandler`) — accepts first incoming connection only, rejects subsequent ones (first-receiver-wins). Holds a `tokio::sync::Mutex<Option<mpsc::Sender<ChatMessage>>>` as the "outbox handle" once a peer connects.
- `run_chat_session(conn, side, outbox_rx, label_self, label_peer_hint)` — async fn:
  - Sends `Hello`, awaits peer `Hello`, emits `chat_connected` event with peer's label
  - Spawns reader task: read inbound frames, emit `chat_message_received` events
  - Spawns writer task: pull from outbox mpsc, send outbound frames
  - On `Bye` either direction or stream close: emit `chat_disconnected` / `chat_closed`

**Extend the stdin watcher in `main.rs`:**

Today: a thread reads stdin into a discard buffer, exits on EOF (parent-death detection).

Tomorrow: that thread becomes a line-reader that:
- On EOF → exit (unchanged)
- On line beginning with `OX_CMD ` → parse remainder as JSON, dispatch to a shared command channel
- Otherwise → ignore (preserves backward compat with any external pipe)

**Commands the watcher dispatches:**
```json
{"type":"chat_send","body":"hello"}      // push to outbox
{"type":"chat_stop"}                     // close chat with Bye
{"type":"stop_send"}                     // gracefully close blob serving
{"type":"stop_receive"}                  // cancel download
```

**Wire chat into `run_send`:** add `.accept(b"orbitxfer/chat/1", ChatProtocol::new(...))` to the existing `Router::builder` chain. Process stays alive until *both* `stop_send` and `stop_chat` conditions are met (or stdin EOF).

**Wire chat into `run_receive`:** after the existing preflight + before/during the download, attempt a second connection on `orbitxfer/chat/1` to the same sender NodeID. If it fails, emit `chat_unavailable` and continue with transfer. If it succeeds, run `run_chat_session` in parallel. Receiver process now stays alive after `export_complete` until the chat closes (or stdin EOF).

**New events emitted:**
- `chat_unavailable` — chat ALPN connection failed; transfer continues
- `chat_connected` — peer joined, includes their `label`
- `chat_message_received` — `{ body, sent_at_unix_ms }`
- `chat_disconnected` — peer sent `Bye` or stream errored
- `chat_closed` — this side closed; final event for that chat
- `chat_send_failed` — write error on outbound

## Tauri backend changes (`src-tauri/src/lib.rs`)

**Delete:** `start_pair_host` / `stop_pair_host` / `start_pair_join` / `stop_pair_join`, `Slot::PairHost` / `Slot::PairJoin`, `pair_host` / `pair_join` slots in `WindowState`, the `PairHost` branch in `run_sidecar`.

**Modify Stop semantics:** `stop_send` / `stop_receive` no longer kill the sidecar directly. Instead they write `OX_CMD {"type":"stop_send"}` (or `stop_receive`) to the sidecar's stdin, then wait up to **5 s** for graceful exit, falling back to `child.kill()` only if the process is still alive. This is the key change that lets chat outlive the transfer.

**Add:**
```rust
#[tauri::command]
async fn send_chat_message(window: WebviewWindow, state: State<AppState>, body: String) -> Result<(), String>

#[tauri::command]
async fn stop_chat(window: WebviewWindow, state: State<AppState>) -> Result<(), String>
```

Both look up the active sidecar in the window (sender slot first, then receiver) and write the appropriate `OX_CMD` line to its stdin. Tauri's `CommandChild` already supports `write()` for stdin.

## React state (`src/App.tsx`)

**Delete:** every pair-related state declaration (~50), pair listeners (~280 lines), pair UI (~600 lines), pair-related types and helpers.

**Add:**
```typescript
type ChatStatus = "idle" | "connecting" | "connected" | "disconnected" | "unavailable";

interface ChatMessageItem {
  kind: "you" | "peer" | "system";
  body: string;
  at: number;  // unix ms
}

// per-window state
const [chatStatus, setChatStatus] = useState<ChatStatus>("idle");
const [chatPeerLabel, setChatPeerLabel] = useState<string | null>(null);
const [chatMessages, setChatMessages] = useState<ChatMessageItem[]>([]);
const [chatInput, setChatInput] = useState("");
```

**Listeners:** new switch cases inside the existing `send:stdout` and `recv:stdout` handlers (chat events arrive on the same channel as transfer events, distinguished by `type`):
- `chat_unavailable` → `setChatStatus("unavailable")`, push system message
- `chat_connected` → `setChatStatus("connected")`, `setChatPeerLabel(parsed.label)`, push system message "Connected to {label}"
- `chat_message_received` → push `{kind: "peer", body, at: parsed.sent_at_unix_ms}` to `chatMessages`
- `chat_disconnected` → `setChatStatus("disconnected")`, push system message "{label} disconnected"
- `chat_closed` → `setChatStatus("idle")`, push system message "Chat closed"

**Actions:**
- `sendChatMessage()`: optimistic local append `{kind: "you", body: chatInput, at: Date.now()}`, then `invoke("send_chat_message", { body: chatInput })`, then clear input.
- `stopChat()`: `invoke("stop_chat")`.

## Lifecycle / state machine

**Sender process:**
```
idle ──ticket_emitted──► serving (blob ALPN active, chat ALPN waiting)
serving ──first chat peer dials──► serving+chat
serving+chat ──Stop Send (graceful)──► chat_only
chat_only ──Stop Chat or peer Bye──► process exits
serving+chat ──Stop Chat──► serving (no chat)
serving ──Stop Send──► process exits (no chat ever connected)
```

**Receiver process:**
```
idle ──start_receive──► connecting
connecting ──blob conn established──► downloading + (chat connecting in parallel)
                                       │
                                       └─► chat connected OR unavailable
downloading ──export_complete──► transfer_done
transfer_done + chat_active ──► chat_only
chat_only ──Stop Chat or peer Bye──► process exits
downloading ──Stop Receive──► cancel download (chat continues if active)
```

**Race-condition handling:**
- Receiver's blob conn fails but chat conn succeeds → chat lives, no transfer (rare; emits both error and chat_connected)
- Chat conn fails but blob succeeds → transfer proceeds, chat shows "unavailable"
- Both fail → existing receive error path
- Sender hits Stop Send mid-download with chat active → receiver sees blob disconnect, chat keeps working until sender's chat side closes
- Sender hits Stop Chat → ChatBye to receiver; receiver shows "Sender disconnected" in chat log, input grays out

## Open questions / explicitly deferred

- **Typing indicators** (`ChatTyping` message) — not in v0.1.85.

- **Rich text / markdown / emoji** rendering — plain text only.

## Implementation notes

1. **Stop semantics change** is the biggest delta from v0.1.83's behavior. Today `stop_send` SIGKILLs the sidecar; tomorrow it asks nicely (graceful close with a 5 s timeout fallback).
2. **Receiver process now long-lived.** Today the receive sidecar exits the moment `export_complete` fires; tomorrow it stays alive for chat. The "Receivers panel" on the sender's side and any logic that watches for receive-sidecar exit may have small assumptions to revisit.
3. **First-receiver-wins** — second-and-later receivers get the file but no chat.
4. **Chat ALPN connection failures should never block transfer** — `chat_unavailable` event, transfer continues normally.
